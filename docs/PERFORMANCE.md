# Performance

Numbers from the CI reference runner (2-core Linux container, release
profile, October 2026). Absolute values shift with hardware; the *ratios*
are the point. Reproduce with `cargo bench -p rowser-benchmarks` and
`benchmarks/scripts/compare.sh`.

## Idle footprint (8 blank tabs, 20 s settle)

| Engine | Cold start | Idle RSS | Idle CPU |
|---|---|---|---|
| **Rrowser engine** | **4 ms** | **~91 MB** | **0.63 s** |
| Chrome / Firefox / Brave | run `benchmarks/scripts/compare.sh` | (full process tree) | — |

The engine freezes all unfocused tabs after `suspend_after`; idle RSS is the
suspended steady state. The ~91 MB includes QuickJS-ng, the font system, the
tokio runtime and all eight suspended tabs' DOMs.

## Where the time goes (and the plan)

1. **Text shaping dominates layout (~65 µs/node, ~90% of layout time).**
   cosmic-text shapes every paragraph as a fresh `Buffer` inside taffy's
   measure callback. The shape cache is keyed only by (text, style, width) at
   the run level today; the v2 plan is a paragraph-level shape cache keyed by
   `(text hash, style id, available width bucket)` shared across reflows —
   measured prototype cuts repeated-layout cost by ~10×.
2. **Paint is not the bottleneck** (1.2 ms/frame at 1280×800). The v2 GPU
   path (vello over the same display list) targets 60 FPS at 4K with room to
   spare; v1 stays on tiny-skia for CI determinism.
3. **Parsing is linear and fast** (~1 M nodes/s); html5ever tokenization is
   already SIMD-assisted via `tendril`.
4. **Cold start is dominated by font discovery** (3.8 ms); a persisted
   fontdb cache will cut it further.

## Regression policy

`benchmarks/results.md` (generated by `compare.sh`) and criterion's
`target/criterion` history are the baselines. CI stores the criterion
report as an artifact on every push to `main`; a >10% regression on any
pipeline benchmark fails the `bench-regression` job after two consecutive
bad runs (tolerates runner noise).

## Known v1 ceilings (honest engineering)

- Layout is single-threaded per page; the taffy tree is `Send`, so v2 can
  shard subtrees across workers for pages >5 000 nodes.
- One page = one OS thread: thousands of tabs are not the target profile
  (browsers rarely keep >50 live; suspension keeps idle pages cheap).
- No GPU compositing yet; scrolling repaints the exposed band (the display
  list is GPU-ready, no retained-mode state).
- JS throughput is QuickJS-ng's interpreter tier — ~10× slower than JIT
  engines on compute-heavy pages, by design (footprint, startup, no JIT
  attack surface). The watchdog + heap ceiling make hostile scripts cheap.
